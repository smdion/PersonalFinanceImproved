# Fallbacks

Every place Ledgr substitutes a value for one that is missing, sorted by why it is there. RULES review rule 4 sets the bar: a default in money code needs a real absent state, and a missing key that should exist throws or warns rather than becoming $0. A fallback that meets the bar is registered here; one that doesn't is deleted or waits on the item named in its row.

The inventory is generated: `pnpm tsx scripts/fallback-inventory.ts` counts every site by kind and area (`--list` prints each one). Sites are registered by pattern, not by line.

## The four bins

| Bin                 | Meaning                                                                                                                                  | What happens to it                                                                             |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Absent state        | The value can really be missing on any install: a nullable column, an optional input, a sparse map, a cache miss, storage that can throw | Stays; its pattern is registered below                                                         |
| Old stored shape    | A reader for a shape an older version wrote, which an old backup, a restore or a long-lived install can still hold                       | Stays until a migration plus a backup transform converts the shape; then the reader is deleted |
| Impossible state    | A guard for a value the types or the code path already guarantee                                                                         | Deleted (counted by the typed lint's `no-unnecessary-condition` where it can prove it)         |
| Missing money as $0 | A missing amount reads as $0, which moves a figure                                                                                       | Stays until the household-math work gives it a real absent state; changing it moves a figure   |

## The ratchet

`ratchet/no-unregistered-fallback` (`eslint-ratchet.mjs`) counts, per file in `eslint-suppressions.json`:

- `?? 0` and `|| 0` in money paths (`src/lib/pure`, `src/server/services`, `src/server/data`, `src/server/routers`);
- a `catch` (or a promise `.catch`, including `.catch(() => call())`, which returns the call's value) that returns a value, anywhere in `src/`;
- a call to a plaintext-or-encrypted reader (`readMaybe*`), anywhere in `src/`.

Exempt by AST pattern: a sparse Map read (`m.get(k) ?? 0`, owner FQ1) and an accumulator seed (`x = (x ?? 0) + v`, `out[k] = (out[k] ?? 0) + v`). A record read (`rec[k] ?? 0`, `limits[key] ?? 0`) in a money path is counted (owner N6). The counts only fall. A new site either gets a real absent state (a `null` the caller shows as missing, a thrown error, a warning) or is registered here under its pattern in the commit that adds it, with a `Ratchet-raise:` trailer.

Counts when the ratchet landed: 329 sites in 172 files; money paths 261 (`lib/pure` 157, `server/routers` 64, `server/services` 29, `server/data` 11), the UI 34 in aggregate, the rest 34. After v0.10.5's deletions (326), owner N6 narrowed the exemption to Map reads and seeds and counted `.catch(() => call())`, re-recorded once at 398 (money paths 330, the UI 34, the rest 34).

## Old stored shapes (kept until a migration plus a backup transform)

Each stays on every install until its migration and transform ship (planned for v0.10.6); prod's data never proves a shape absent.

| Site                                                          | Covers                                                            | Install shape                                      | Removal condition                                                             |
| ------------------------------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------- |
| `lib/pure/net-worth/year-end-rows.ts` (`perf?.byType ?? {…}`) | Years with no performance rows read the year-end columns          | Year-end rows from before performance finalisation | A migration writes `byType` for those years                                   |
| `lib/pure/investments/performance-annual-rows.ts`             | `account_performance.parent_category` disagreeing with the master | Older rows                                         | A migration from the master                                                   |
| `lib/config/tax-limit-keys.ts` (`taxLimitKey()` undefined)    | `limit_type` rows Ledgr no longer uses                            | Installs with old rows                             | A migration deletes them; the lookup throws                                   |
| `lib/utils/account-name.ts` label rebuild                     | Labels stored before the joint-prefix rule                        | Installs with old labels                           | A migration rewrites the labels                                               |
| `lib/pure/paycheck/per-check.ts` after-tax exempt guard       | After-tax rows flagged exempt                                     | Old backups                                        | A backup transform; the write guard in `routers/settings/deductions.ts` stays |

Every server read of `contribution_active_fields` goes through `readContributionActiveFields`, which throws on a row of another shape (the stored-JSON migration converted or refused every one). The Salary Profile rows the paycheck and projection math read (`server/data/salaries.ts` `fetchSalaryProfile`, `engine-payload/load.ts`, `profile-switches.ts`) go through `checkSalaryEntries`, which throws on a row of another shape (the stored-JSON migration converted or refused every one); the router's editor reads and writers keep the raw row. The writers keep the raw root: `patchEntry` in `routers/contribution-profiles.ts`, `services/contributions/account-edits.ts`, `server/data/delete-references.ts` (removing a deleted record's entries), `refreshEntryRates` in `services/contributions/match-writes.ts` and the profile duplicate in `services/profiles/profile-lifecycle.ts`. They write the whole root back, so a reader that dropped a key would change stored data.

The four stored-shape readers (`lib/db/stored-setting.ts`, `stored-strategy-key.ts`, `stored-salary-entries.ts`, `stored-active-fields.ts`) check through one reader, `lib/db/stored-shape.ts` `readStoredShape`: it takes any value, returns a fitting one as itself, and logs a refused one once per process and marks it as stored. `passOnAsStored` is the one place a refused value passes on; once a shape's migration converts every row, its reader throws on a refused read instead. A reader is tested against a JSON-null, array, scalar and double-encoded-string root from its first commit.
